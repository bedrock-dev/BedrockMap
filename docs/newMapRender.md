# 2.5D 体素大地图渲染方案文档

## 一、方案概述

### 1.1 场景定义

- **视角**：平面固定俯视，相机不旋转、不缩放
- **画面**：只能看到体素方块的顶面，看不到侧面
- **地图规模**：最大 4K 平面（3840 × 2160），一个像素一个体素
- **渲染方式**：不构建 Mesh，不使用硬件光追

### 1.2 核心思路

本方案将整个体素世界抽象为**两张核心数据图**：

- **地表图**：每个格子的方块类型
- **高度图**：每个格子的高度值

渲染时，用一张**全屏 Quad** 配合 **Fragment Shader**，根据屏幕坐标反算地图坐标，采样地表图和高度图，合成最终画面。阴影和 AO 通过**离线烘焙**写入纹理，运行时零开销。

**整个场景只有一个 Draw Call。**

### 1.3 为什么不用 Mesh

- 只能看到顶面 → 没有立体几何需求
- 固定视角 → 不需要动态几何
- 不建 Mesh → 数据更新时无需重建顶点缓冲
- 数据即纹理 → 动态加载和更新极其轻量

## 二、数据设计

### 2.1 核心数据图

| 数据           | 内容           | 建议格式           | 说明           |
| -------------- | -------------- | ------------------ | -------------- |
| 地表图         | 方块类型 ID    | `uint8` / `uint16` | 决定颜色/材质  |
| 高度图         | 每格高度值     | `uint8` / `uint16` | 决定遮挡、位移 |
| AO 图          | 烘焙环境光遮蔽 | `uint8`            | 离线生成       |
| 阴影图         | 烘焙阴影       | `uint8`            | 离线生成       |
| 光照图（可选） | 烘焙光照       | `uint8` / `vec3`   | 离线生成       |

### 2.2 分辨率与显存估算

以 3840 × 2160 为例：

| 纹理     | 格式     | 大小       |
| -------- | -------- | ---------- |
| 地表图   | `uint16` | ~16 MB     |
| 高度图   | `uint16` | ~16 MB     |
| AO 图    | `uint8`  | ~8 MB      |
| 阴影图   | `uint8`  | ~8 MB      |
| **合计** |          | **~48 MB** |

**结论**：4K 全图完全可以一次性加载进显存，无需动态加载。

### 2.3 数据组织（可选动态加载）

如果未来地图更大或显存受限，可按 Chunk 分块：

```
世界地图 (4K)
  └── Region (512×512)
        └── Chunk (64×64)
              └── Tile (单格)
```

每个 Chunk 对应纹理图集中的一块区域，可独立加载、卸载、更新。

## 三、渲染管线

### 3.1 整体流程

```
┌─────────────────────────────────────────┐
│  1. 全屏 Quad（4 顶点）                  │
│  2. Fragment Shader：                    │
│     - 屏幕坐标 → 地图坐标                │
│     - 采样地表图、高度图、AO、阴影       │
│     - 高度位移 + 光照合成                │
│  3. 输出最终颜色                         │
└─────────────────────────────────────────┘
```

### 3.2 全屏 Quad

- 4 个顶点，覆盖整个视口
- 顶点属性只需位置（`vec2`）和 UV（`vec2`）
- 一次 `vkCmdDraw`，一个 Draw Call

### 3.3 Fragment Shader 逻辑

```glsl
// 伪代码
vec2 mapCoord = screenToMap(fragUV);       // 屏幕 → 地图坐标
uint terrain  = sampleTerrain(mapCoord);   // 采样地表图
float height  = sampleHeight(mapCoord);    // 采样高度图
float ao      = sampleAO(mapCoord);        // 采样 AO
float shadow  = sampleShadow(mapCoord);    // 采样阴影

vec3 baseColor = lookupColor(terrain);     // 方块类型 → 颜色
vec2 offset    = heightToOffset(height);   // 高度 → 屏幕位移（2.5D 立体感）
vec3 finalColor = baseColor * ao * shadow;
```

### 3.4 高度位移（2.5D 立体感）

高度图除了算 AO 和阴影，还能产生视觉位移：

- 高处格子沿固定方向（如斜上方）偏移若干像素
- 产生轻微的立体感，无需真正的 3D 几何
- 偏移方向由固定光照方向决定

### 3.5 坐标映射

固定俯视下，屏幕坐标到地图坐标是一个简单的线性变换：

```
mapX = (screenX - cameraOffsetX) * scale
mapY = (screenY - cameraOffsetY) * scale
```

无需透视投影，无需矩阵变换。

## 四、AO 烘焙

### 4.1 原理

2.5D 高度场下，AO 取决于**邻域高度差**：

- 周围格子比自己高 → 产生遮蔽
- 高度差越大 → AO 越强

### 4.2 计算方法

对每个格子，检查周围 8 个邻居：

```cpp
float ao = 0.0;
for (each neighbor in 8 directions) {
    float diff = neighborHeight - currentHeight;
    if (diff > 0) {
        ao += clamp(diff / maxDiff, 0.0, 1.0) * weight;
    }
}
ao = 1.0 - ao * aoStrength;
```

### 4.3 输出

- 将 AO 值写入 `uint8` 纹理
- 运行时直接采样，零计算
- 因视角和光照固定，AO 只需烘焙一次

---

## 五、阴影烘焙

### 5.1 原理

固定方向光下，每个格子的阴影取决于**沿光方向是否被更高的格子挡住**。

### 5.2 四叉树加速

```
1. 将高度图构建为四叉树
2. 对每个格子，沿光方向投射一条射线
3. 用四叉树快速跳过不需要检测的区域
4. 判断是否被遮挡
```

四叉树的作用：

- 快速跳过远处不可能遮挡的区域
- 快速定位可能遮挡的局部范围
- 把 O(n) 的逐格检测降到接近 O(log n)

### 5.3 阴影方向

固定光照方向下，阴影方向固定：

- 例如光从左上角来 → 阴影向右下延伸
- 每个格子的阴影只取决于其右上方的格子

### 5.4 输出

- 将阴影值写入 `uint8` 纹理（0 = 全阴影，255 = 无阴影）
- 运行时直接采样
- 只需烘焙一次（静态地图）

### 5.5 软阴影（可选）

- 对阴影边缘做多次采样取平均
- 或多级四叉树采样，产生半影效果
- 烘焙时完成，运行时零开销

---

## 六、动态加载（可选）

### 6.1 何时需要

- 地图超过 4K，或显存受限
- 地形会动态变化

### 6.2 核心优势

因为没有 Mesh：

- 数据更新只需**更新纹理局部区域**
- 不需要重建顶点缓冲
- 不需要重新提交绘制命令

### 6.3 纹理图集方案

```
+----+----+----+----+
| C0 | C1 | C2 | C3 |
+----+----+----+----+
| C4 | C5 | C6 | C7 |
+----+----+----+----+
| ...                |
+----+----+----+----+
```

- 每个 Chunk 占图集中的一块
- 加载 = 往图集写数据
- 卸载 = 标记区域可复用

### 6.4 更新流程

```
1. 检测需要加载/卸载的 Chunk
2. 生成或读取 Chunk 数据
3. 计算 AO、阴影（仅受影响的 Chunk）
4. 用 staging buffer 上传到纹理图集
5. 标记 Chunk 状态
```

### 6.5 上传优化

- 用 **staging buffer + 异步传输队列**
- 分帧上传，避免卡顿
- 预加载相邻一圈 Chunk，避免边缘闪烁
- 单个 64×64 Chunk 的 `uint8` 数据仅 4KB，开销极小

## 七、Vulkan / Qt 实现

### 7.1 使用 QVulkanWindow

`QVulkanWindow` 负责：

- 窗口管理
- 设备与队列创建
- 交换链管理

渲染逻辑全部自己实现。

### 7.2 资源清单

| 资源     | 用途                     |
| -------- | ------------------------ |
| 顶点缓冲 | 全屏 Quad（4 顶点）      |
| 索引缓冲 | 2 个三角形               |
| 纹理     | 地表图、高度图、AO、阴影 |
| 采样器   | 最近邻（保持像素感）     |
| 描述符集 | 绑定纹理                 |
| 管线     | 一个图形管线             |
| Uniform  | 相机偏移、缩放           |

### 7.3 渲染循环

```
startNextFrame():
  1. 更新 Uniform（相机偏移）
  2. 绑定管线、描述符集
  3. 绑定顶点/索引缓冲
  4. vkCmdDrawIndexed(6, 1, 0, 0, 0)
  5. frameReady()
```

**每帧只有一个 Draw Call。**

### 7.4 纹理上传

```cpp
// 创建 staging buffer
// 填充数据
// vkCmdCopyBufferToImage
// 转换 layout 为 SHADER_READ_ONLY_OPTIMAL
```

## 八、性能预期

| 指标            | 预期值                 |
| --------------- | ---------------------- |
| Draw Call       | 1                      |
| 顶点数          | 4                      |
| 三角形数        | 2                      |
| 纹理采样        | 每像素 4~5 次          |
| 显存占用        | ~50 MB（4K 全图）      |
| 运行时 CPU 开销 | 极低（仅更新 Uniform） |
| 帧率            | 4K 60fps 轻松达成      |

性能瓶颈几乎全在 Fragment Shader 的采样和合成上，现代 GPU 完全无压力。

## 九、方案对比

| 方案                     | 是否适合           |
| ------------------------ | ------------------ |
| 建 Mesh + 光栅化         | ❌ 多余            |
| 硬件光追                 | ❌ 完全不需要      |
| 软件高度场求交（四叉树） | ✅ 用于烘焙阴影/AO |
| 全屏 Quad + 高度图       | ✅ 最终渲染方式    |
| 离线烘焙 AO + 阴影       | ✅ 运行时零开销    |

## 十、实施步骤

1. **准备数据**：地表图 + 高度图
2. **烘焙 AO**：按邻域高度差计算，写入纹理
3. **烘焙阴影**：四叉树 + 高度场求交，写入纹理
4. **搭建渲染**：全屏 Quad + Fragment Shader
5. **实现坐标映射**：屏幕 → 地图坐标
6. **合成画面**：采样 + 高度位移 + 光照
7. **（可选）动态加载**：纹理图集 + 局部更新
8. **调优**：采样精度、位移强度、AO/阴影强度

---

## 十一、关键注意事项

1. **采样器用最近邻**：保持体素像素感，避免模糊
2. **纹理格式对齐**：`uint8/uint16` 注意 Vulkan 格式支持
3. **Y 轴方向**：Vulkan 裁剪空间 Y 向下，注意地图坐标方向
4. **高度位移方向**：固定光照方向决定偏移方向，保持一致性
5. **动态更新**：优先用局部纹理更新，避免整图重传
6. **预加载**：相机移动时提前加载相邻 Chunk

---

## 十二、总结

本方案的核心是**把 3D 问题降维成 2.5D 纹理问题**：

- 不建 Mesh
- 不用硬件光追
- 数据即纹理
- 光照、AO、阴影全部离线烘焙
- 运行时一个 Draw Call

这是固定俯视体素大地图场景下**最简洁、性能最好、最易维护**的方案。
